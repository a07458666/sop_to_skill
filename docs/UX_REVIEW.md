# UX / Product Review — Information Architecture & User Story 翻新

狀態:提案(2026-06)。本文是 UI/UX + PM 視角的產品檢視與 user story 重做,作為介面翻新的依據。
產品定位與技術路線見 `docs/PRODUCT.md` / `docs/ROADMAP.md`。

## 1. 問題診斷:功能導向,而非旅程導向

目前 Converter / Simulator 兩頁把**所有功能平鋪**,每個區塊配一大段灰字說明。
新使用者落地會同時看到 7+ 個重型區塊(行銷概念、規則編輯器、編譯沙盒、品質報告、
流程圖、整合設定、掛載、模擬器),不知道「先做什麼、做完得到什麼」。

| 問題 | 現況 | 後果 |
| --- | --- | --- |
| 行銷凌駕任務 | Converter 第一屏是「為什麼要轉換」概念圖 | 想動手的人被擋在說明前 |
| 進階功能放主線 | `sop_rule.md` 規則編輯器擺很前面 | 99% 的人不改規則,卻先看到它 |
| 報告是資訊傾倒 | 品質報告整段 markdown 攤開 | 應是「通過 / N 問題」的狀態,不是論文 |
| 每區一段灰字 | 每個 section 都有 2–3 行解釋 | 視覺噪音淹沒真正的操作 |
| 重複元件 | 流程圖在兩頁各出現一次 | 不知道哪個是主角 |
| 概念重疊 | 整合設定 + MCP 掛載分兩塊 | 同一件事(設定工具)被切兩半 |

## 2. 北極星一句話

> 「我貼上 SOP,它立刻變成一張 AI **無法跳步**的可執行流程圖,而且我能當場跑給自己看。」

## 3. 角色 (Personas)

- **P1 製程工程師 / SOP 作者**(主):擁有 SOP,要把它變成可強制執行的 skill 並確認正確。
- **P2 自動化 / Agent 工程師**:接好 API/MCP 整合並測試執行。
- **P3 製程主管 / 審核者**:核准、審核核准閘、審核版本變更(治理)。

## 4. 重做後的 User Story(三幕旅程 + 治理)

### 第一幕 — 編譯 Compile(把 SOP 變合法 Skill)
- **US1**(P1):我貼上/編輯 SOP,一鍵看到它編成 SKILL.md + flow.json,並立刻知道「能不能用」(通過 / 幾個問題)。
- **US2**(P1):有問題時(缺分支、signal 不在 returns),我看到可定位的精簡提示,而不是一整頁報告。

### 第二幕 — 看懂 Review(確認流程是我要的)
- **US3**(P1/P3):我用流程圖看懂整個狀態機,點節點就看到它呼叫什麼工具、怎麼判讀回傳、跳去哪。
- **US4**(P3):我一眼看出哪些步驟是人機協同核准閘(硬阻斷)。

### 第三幕 — 證明 Run(證明 Agent 不會亂跑)
- **US5**(P2):我設定每個工具的 API/MCP 與 I/O 並掛上 server。
- **US6**(P1/P3):我模擬 Agent 執行,親眼看到三個「驚艷時刻」:非法步驟被擋 / 核准閘卡住直到我核准 / 依回傳值自動路由。

### 第四幕 — 治理 Govern(進階,不在主線)
- **US7**(P3):我比較兩版 SOP 的狀態機差異,審核後才放行(`flowdiff`)。
- **US8**(P3):系統依執行缺口提案 SOP 修訂,我核准後重編譯(`evolve`)。

## 5. 新資訊架構(漸進揭露)

```
頂部:三步進度條  ①編譯 → ②看懂 → ③證明        (治理 在右上「進階」)

① Compile   [SOP 輸入] ──編譯──▶ [結果:✅通過 / ⚠️2 問題] + 下載
            (規則編輯器、概念說明 → 收進「進階 / 關於」摺疊)

② Review    [流程圖 = 主角]  點節點 → 側欄細節
            品質問題 = 流程圖上的紅點 + 精簡清單(非整頁報告)
            核准閘 = 節點上的琥珀色徽章

③ Run       [整合設定 + 掛載 合併成一塊] → [模擬器]
            把「非法被擋 / 核准卡關 / 回傳路由」做成醒目高亮
```

設計手法:
- 每個 section 灰字縮成一行,或移到 ⓘ tooltip。
- 報告改成**狀態徽章 + 可展開**(`<details>`),預設收起。
- 行銷(概念)與進階(規則編輯器)收進摺疊,不佔主線。
- 整合設定 + MCP 掛載合併為「整合與掛載」一個區塊。
- 流程圖是貫穿②③的主角元件,視覺權重最高。

## 6. 落地階段

1. ✅ **去雜訊 pass**:漸進揭露(概念/規則收摺疊)、品質報告徽章化、文案精簡、整合+掛載合併為兩步。
2. ✅ **三步旅程**:頂部 ① 編譯 → ② 看懂 → ③ 證明 進度條(`showStep`);Converter 承載 ①②(步驟面板切換),Simulator 為 ③;`index.html#review` 深連結步驟 ②。
3. ✅ **治理進階區**:`governance.html`(進階 · 治理)用 `flowdiff` 的 JS port 比較兩版 flow.json,並把差異疊到流程圖、再渲染「演化建議」(把差異寫回 SOP 的修訂清單,evolve 閉環的 web 半);入口在 stepper 下方。完整自動提案仍在 `evolve.py` / `optimizer.py`。
4. ✅ **視覺減法(calm redesign)**:解決「資訊量爆炸」。色彩收斂為 1 主色 + 中性灰(API/MCP/狀態改用低飽和色)、移除背景漸層與發光、扁平化卡片(去毛玻璃/降陰影)、縮小標題級距與留白;流程圖節點由五行精簡為「標題 + 一行 meta」並縮小尺寸;移除通用流程圖例;Simulator 的「整合與掛載」收進預設摺疊的「進階」,預設只聚焦載入 + 模擬器。

## 7. 成功指標

- Time-to-first-compile:落地到第一次成功編譯的時間下降。
- 首屏可理解性:新使用者能在不讀說明下說出「下一步該做什麼」。
- 任務完成率:編譯 → 看懂 → 模擬一次跑通的比例。
